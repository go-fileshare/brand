# go-fileshare brand assets

The org mark is a **disk image with three paths leaving it** — one image,
served several ways — on the cyan systems-family gradient (`#22CCE2 → #0079A8`),
the same family `go-filesystems`, `go-volumes` and forty other sibling orgs
use. The colour was not invented for this org: it serves `go-filesystems`'
images, so it takes its siblings' colour.

The three rays start at three different points on the disk rather than meeting
at one. A convergence reads as an **arrowhead**, and an arrowhead beside a disk
points the wrong way: into it, as though this were an importer.

Per-repo marks are **the org glyph declined** — the same disk and rays, shrunk
into the top region, over a white name plate. They are not custom glyphs,
deliberately: a distinct mark per repo breaks the family at a glance.

## Formats

- **SVG** — `svg/color`, `svg/white` (white, transparent), `svg/black`
- **PNG** 16→1024 px, 3 variants — `png/<variant>/<size>/`
- **JPG** (colour, white background) — `jpg/<size>/`
- **ICO** (Windows) — `ico/`
- **ICNS** (macOS) — `icns/`
- **GitHub avatar** 512 px — `avatar/`
- **Social preview** 1280×640 — `social/`

Two subjects: the org mark and one per repository.

## How these are made

Generated by **`logos/brandgen`**, a Go program built on this fleet's own
packages — [`go-gfx/gfx`](https://github.com/go-gfx/gfx) for the SVG raster,
the resizes and the ICO/ICNS containers, and
[`go-opentype`](https://github.com/go-opentype/opentype) for the name plates.
No Pillow, no `sips`, no `iconutil`: it runs anywhere Go runs.

`gfx/svg` deliberately does not render `<text>` — a rasteriser that silently
picks a font renders a different document on every machine — so each `<text>`
is converted to real glyph outlines before rasterising, in **Inter**, which is
embedded in `go-opentype/fonts`. The SVG that ships keeps its `<text>`: that is
the editable form, and a browser has the font stack it names.

This org's mark is also why `gfx/svg` draws `<ellipse>` at all. It did not
until [go-gfx/gfx#41](https://github.com/go-gfx/gfx/pull/41): the element was
missing from the switch, and an unimplemented shape is skipped rather than
guessed at — so the disk simply vanished and the mark read as a rune.

## What CI checks

The marks are shown on somebody else's page, where a blank or mis-sized file
reads as a broken image and nothing here would say so. So every pull request
checks, with no image library installed: every avatar is 512×512 and large
enough not to be a failed render (dimensions come from the PNG's IHDR chunk,
the first 24 bytes); every subject has the whole format matrix; every per-repo
SVG has an avatar and every avatar an SVG; and every per-repo SVG is the org
mark with only the name changed. That last one is the family rule, which would
otherwise be kept by remembering it.
